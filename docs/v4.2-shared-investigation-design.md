# v4.2：按行为负责与共享调查的后续设计

状态：`d70bb49` 已实验性实现单主责选项、共享调查、跨单元反证和相关重审；远端完整后端 CI 为 **3917 passed、3 skipped**。自动语义行为分组和 QuestionAssistant 委派尚未交付，新路径尚未通过真实 PR 验收。旧 `a8ce20d` 评测在多个单元进入 error 后保留独立账本并停止；新代码同 PR 空状态测试及同绑定续跑均因中转故障 partial，正在等待服务恢复。生产默认仍为 `legacy`。具体实现、限制及账本见 [架构记录 19.17](v4.2-architecture.md#1917-共享调查责任粒度与来源行号)。

## 已确认的问题

- `v42-units-6` 支持按显式 `transaction_id` 合并变更，但固定快照生成链路没有产生该字段。Cal.com #14740 的 24 个区域因而被拆成 15 个文件责任单元；这与[原设计](v4.2-architecture.md)中“小 PR 默认一个 Reviewer、相关行为优先合并”的意图不一致。文件边界只是所有权安排，不说明行为独立。
- 一份运行中审计快照包含 32 次成功响应。15 份唯一 diff 的原文在实际模型输入里出现约 157,669 UTF-8 字节，唯一内容约 24,102 字节；该对比只衡量原文重复出现，不等价于 token、价格，或证明所有重复读取均不必要。相同原文的存储去重和其他任务曾经读取，都不会自动节省当前任务的模型输入。
- 共享目录目前主要提供原始引用和不可信导航，消费者必须主动查询；它没有一个可原子认领、版本化交接的跨文件调查项。多任务可以各自重复追踪同一问题，而有价值的调查不一定在其他任务需要时可见。
- 另一任务新增潜在反证后，仅将其放入共享目录，不会自动改变某个 Case 已绑定的来源集合和核验许可。只有显式登记相关依赖、原子失效和重审，才能使这种已知冲突影响发布；系统不能声称发现了全部潜在反证。

这些观察支持修改任务组织和共享交接，不能单独证明哪次阅读无用、当前实测必然失败，或新设计必然降低成本。已有四次候选提交被错误接口拒绝的独立诊断见 [Cal.com 候选诊断](v4.2-calcom-diagnostic.md)。

## 目标和非目标

让一次明确的行为调查有持续责任人和可交接状态：以固定变更清单为完整性基础，把相关区域尽量放进同一个真实任务；只有存在具体独立问题时才委派调查，结果回到共享工作板。来源、推测、未知、候选与独立裁决分开保存。可以随时跨文件、跨版本补取证，也可以并行核验已经提出的候选。

不以模型请求数、token、工具次数、候选数或结果长度作为审查停止条件；不能因导航分页或分组而丢掉显式请求的来源。单个模型请求受中转延迟影响时要可恢复、可重试，并如实记录失败及未知用量。不得用“已读取”“图中无边”或覆盖率代替发现、理解和验证。

## 四类持久对象

1. **固定清单与原文。** run 绑定仓库、base、head、两个工作区和完整变更清单的哈希。区域包含新增、删除、重命名表示及无法解析的结构性变更；每个区域恰有一个主责任。原始来源单独存储，保持版本、路径、行范围、正文哈希、环境和来历。
2. **行为规划。** 提出区域分组、主责和需要进一步调查的关联，仅决定任务组织，不是事实证明。默认先考虑一个真正的全局责任任务；对具有明确业务边界的独立行为可拆为多个任务，同一行为链优先共同负责。规划不得修改原始清单、虚造 `transaction_id` 或把目录相近当作事务关系。控制器校验所有区域恰好分配一次、已知重叠范围及真实共同事务不被违规拆分；规划缺项、快照不一致或结构不可用时保留未完成状态。
3. **共享调查项。** 对具体问题保存控制器 ID、run 与任务范围、当前负责人和租约、修订号、问题、带来源引用的观察、未解边界、状态及更正原因。认领、更新、交接和撤销使用持久事务和版本检查；同一身份的重试幂等，不按近义文本合并不同问题。关联任务主动取得相关视图和可分页目录；视图的选择条件与未载入内容可见，目录项始终是不可信导航。
4. **Case、独立核验与交付。** 候选单独绑定触发条件、机制、影响、支持来源和已知反证。独立 Verifier 获取具体主张和固定原文，自行判断，不接收共享笔记、上游置信度或其他角色的结论。最终交付依赖最新 Case、来源、反证、核验和责任回执；未解决冲突保持 partial。

## 关系与共享的边界

固定源码能够确定路径、变更区间，以及经解析器成功解析的部分语法关系。关系目录应记录解析器版本、base/head、源和目标位置、原始来源与 `resolved`、`ambiguous` 或 `unavailable`；别名、重导出、动态调用、缺依赖和解析失败必须保留未知。语法边不证明业务可达，缺边不证明没有交互；具体契约和行为仍须由任务调查。关系只供发现与规划，不能直接生成事实、候选或裁决。

跨任务共享正文时，本地 blob 和固定源码采集可以复用；需要据此作决定的消费者，仍须在自己的有效任务和租约内，通过一次成功模型请求实际收到对应原文或完整分页，并留下可验证的送达记录。同批刚读到的工具结果、缓存命中、旧任务的回执和只看目录都不等于送达。不要把服务商报告的 `cache_read_tokens` 与本地缓存或实际少发的 token 混为一谈。

对于已明确关联到 Case 的新增或撤销来源、反证和冲突，必须在同一数据库事务中记录依赖、使受影响的旧授权失效并安排重审；只修改无关导航不应让全部 Case 重新采样。发布冻结事务应重新检查依赖版本及 pending 状态。数据库事务不覆盖外部平台发送：发送状态不明时需恢复核对，不能声称跨系统 exactly-once 或盲目重发。

## 调度、恢复与兼容

固定规划在首次安装时持久化；任务、原生工具交换、租约和失败回执可在进程退出后恢复。共享调查的过期租约可安全认领，旧持有者不能继续写入。出现新证据时只重开明确受影响的区域、义务和 Case；重复提交、时间戳或解释改写本身不构成新证据。

新规划器和共享调查语义必须进入新的运行身份与策略；已经启动的旧 checkpoint 按原有规则恢复，不能把新导航或来源静默写进旧账本。默认生产行为保持不变，先在 opt-in 模式验证。拆分或合并任务均不能删除固定清单责任，也不能省略独立的跨行为整合；未登记的语义联系仍存在漏发现风险。

## 实施与验收顺序

1. 离线实现并测试行为规划的责任完整性、共享调查认领/修订/恢复、真实原文送达和显式依赖失效；旧策略保持原语义。测试删除、重命名、二进制、同 hash 不同版本、缺页、不可用来源、过期 lease 和并发发布。
2. 使用录制轨迹或脚本模型测试一个行为链中的多区域共用一次调查、另一个任务显式获取共享线索并读取原文、发现反证后只重开受影响结果。共享索引、同批读取和跨任务送达伪造均应被拒；空关系图不能制造完成回执。
3. 以同一固定 PR/head、模型和评测条件从空状态复测，并保留全部物理请求。分别记录完成回执、候选、独立裁决、最终评论、每次输入正文及服务商报告的 input/output/cache-read tokens、失败或中断的未知用量；完整结果才运行独立裁判。
4. 与既有方案做配对比较，再使用未见集评估漏报和误报。仅有离线单测、存储去重、较少任务或某个中途快照都不能证明质量和成本改善，更不能据此宣称优于 v3。
